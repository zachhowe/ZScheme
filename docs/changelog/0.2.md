# 0.2 — 2026-07-05

The largest release so far, and the one with the most breaking changes. Three themes: the
language surface was renamed toward Racket conventions, a real web stack (`aspnet`, `di`,
`logging`, `json`) was built on top of `import-clr`, and both backends were pushed through
another long round of fuzzer- and Roslyn-verified codegen fixes.

## Breaking changes

- **`fn` renamed to `lambda`**, and function types now use infix syntax.
- **Type declaration forms take a `define-` prefix**: `define-class`, `define-struct`,
  `define-interface`, and so on.
- **`let` and `let*` require a parenthesized binding list**, standard-Scheme style.
- **Collections renamed and realigned with Racket**:
  - The `ImmutableList` wrapper became **`TreeList`**, and the linked list was promoted to
    the default **`List`**.
  - **`stdlib/array` → `stdlib/vector`**, `Mutable-Array` → `Mutable-Vector` (underlying
    CLR types `ImmutableArray<T>` and `T[]` unchanged).
  - **`Map` / `Mutable-Map` → `Hash` / `Mutable-Hash`**, aligned with the Racket hash API.
  - `TreeList` / `Mutable-TreeList` APIs expanded toward Racket parity.
- **Collection type aliases moved out of the compiler into the stdlib** via
  `define-type-alias`; the compiler discovers them through a `TypeAliasRegistry` rather
  than hardcoded string literals, with a built-in `Clr-Array` alias as the fallback for
  CLR arrays.
- **`main` is the entry point directly**, with a validated signature — no wrapper.
- **The IL backend is selected via the manifest** (`backend "il"`) rather than being
  inferred from `output-type`.

## Added — language

- **`typeof`** for `System.Type` values.
- **`(delegate ...)`** syntax for CLR delegate types, with ZScheme functions automatically
  coerced to delegates when passed to CLR methods.
- **`(use ...)` and `(use* ...)`** for deterministic disposal, including async `use` on the
  IL backend via a state-guarded `finally`.
- **`(when ...)` and `(unless ...)`** macros.
- **Signature-directed overload resolution** at the call site, for both ZScheme functions
  and CLR members, with generic methods resolved at the call site instead of at import time.
- **Variadic arithmetic and comparison operators**; classic Scheme aliases added.
- **Multiple body expressions in `let` and `let*`** without a wrapping `begin`.
- `compose` split into a curried form and an immediate-application form.
- `result`: `unwrap-or` and `unwrap-or-none`.

## Added — packages

- **`aspnet`** — ASP.NET Core minimal APIs bound directly through `import-clr` (an initial
  C# bridge was written, then removed once the interop was good enough to do without it).
  Includes DI / service registration bindings, `CancellationToken` threading through the
  lifecycle, structured `ILogger` logging, and an integration test suite.
- **`di-abstractions` / `di`** and **`logging-abstractions` / `logging`**, extracted from
  `aspnet` as standalone packages.
- **`json`** moved from `aspnet` into the stdlib, with generic serialize/deserialize.

## Added — tooling

- **Roslyn compile-verification harness** in the `CSharpEmitter` tests — emitted C# is
  actually compiled, not just string-matched.
- **CSharpier pre-commit hook** for `.cs` formatting, with a PowerShell installer.
- `docs/COMPILER-PIPELINE.md` documenting the pipeline and the inline-vs-precompiled module
  paths; `docs/FUZZER.md` documenting the fuzzer, with a standing requirement to keep both
  current.
- `install-packages.ps1` auto-discovers and topologically sorts packages.
- Per-session ZScheme cache directory override.
- `zs build` emits an executable for `(output-type "Exe")` packages, and
  `runtimeconfig.json` generation moved into the compiler.
- Fuzzer generators added for `typeof`, `(delegate ...)`, and the `use` / `use*` forms;
  several fuzzer generator bugs fixed (stdlib call naming, `vector-append` semantics,
  `compose` arity, `define-struct` / `define-class` spellings, hex seeds).

## Changed — internals

- **`(object ...)` is lowered to synthesized classes during IR lowering**, not in the
  emitters.
- **IR lowering is the single authority for CLR overload resolution.**
- The two type mappers were unified behind a shared `ITypeFactory` traversal, with shared
  type-name conversion helpers.
- `IlEmitter`'s ambient `_current*` state was bundled into an `EmitContext` record and
  threaded through emission as a parameter; the ambient field was deleted.
- Async state-machine codegen extracted into `IlAsyncEmitter`.
- Colliding emitted identifiers and type names are disambiguated on both backends, while
  single-letter type names survive module export.
- `import-clr` annotations are validated against the real CLR member.
- Redundant `(begin ...)` wrappers removed from `let` / `let*` / `lambda` bodies.

## Fixed

- **Cross-module**: transitive dependencies included in library compilation and package
  testing; transitive ZScheme dependency prefixes resolved; prefixed local-package deps
  resolved in `build --manifest`; cross-module interface and base-class codegen;
  precompiled module class references fully qualified in C#; precompiled module namespaces
  no longer emitted as `using` directives; imported union constructor patterns infer
  correctly; a failing transitive import no longer reports a false "circular module
  dependency".
- **C# codegen**: local parameters shadow same-named imported functions; CS0102 when a
  function name collides with a same-module type; CS0201 from Unit literals and discarded
  Unit-typed expressions in statement position; discarded property/indexer gets emitted as
  bare statements; type arguments emitted on overload-resolved non-generic calls and on
  calls to shadowed function params; match-arm pattern bindings scoped so shadows don't
  trigger CS0136; nested top-level `let` bindings out of scope; discarded non-Unit values
  in statement position; `*` and `<` sanitized in identifiers; inherited class fields
  emitted as method calls inside object bodies.
- **IL codegen**: closures captured inside generic methods; field access on precompiled
  record types; nested lambdas and object constructors leaking async `MoveNext` context;
  `let` bindings scoped so inner shadows don't clobber the outer slot; match-arm bindings
  scoped so they don't leak past the match; lambda closures nested under the wrong type in
  class constructors; missing box for value-type arguments passed to reference-type
  parameters; `Nullable<T>` member access emitting IL that segfaulted RyuJIT.
- **Both backends**: immediately-invoked functions flattened; `with-handlers` in statement
  position emitted as a bare `try`/`catch` rather than an IIFE; constant `/` and `%` forced
  to runtime evaluation so C# and IL agree on overflow behaviour.
- Arity-mismatched lambdas passed to generic delegate parameters are rejected; delegate
  parameter leaf types unify into unbound lambda type variables.
- Record-type `let` annotations resolve to the record type, not its constructor.
- Attribute forms inside `begin` blocks.
- `import-clr` validation was being contaminated by a process-wide reflection scan.
- `import-clr` properties inherited from a base interface now resolve; `(framework ...)`
  deps resolve in the LSP.
- LSP ambiguous-overload errors when editing prelude modules; prelude type aliases
  registered in the package compile path.
- Zed extension grammar repo path; the pre-commit hook wiping already-formatted `.cs` files.

## Known limitations documented

- `define-async` inside `let` bodies is unsupported.
- `KNOWN_CODEGEN_BUGS.md` and `IL_REFACTOR.md` were removed once everything they tracked
  was fixed. Fuzzer-found bugs are now filed as reports under `issues/`, worked through by
  the `fix-issue` and `fuzz-triage` skills.
