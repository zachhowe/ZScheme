# 0.1.4 — 2026-04-09

The release that retired the built-in error-handling forms in favour of stdlib macros, and
added tuples and a pure-ZScheme linked list.

## Added

- **Tuple types**, backed by .NET `ValueTuple`, with `values` in editor highlighting and
  LSP completions.
- **`stdlib/slist`** — a pure ZScheme singly linked list with `cons`, `head`, `tail`,
  `rest`, `length`, `nth`, `reverse`, `map`, `filter`, `fold`, `append`, `concat`, a
  variadic constructor, and conversion functions. 24 test cases and an example ship with it.
- **Multi-module import syntax**: `(import foo bar baz)`.
- **`with-method-impl` macro.**
- **READMEs** — a top-level one with a language overview, feature list, and usage guide,
  plus per-package READMEs for stdlib, zunit, and http.
- A script to bump individual package versions.

## Changed

- **`try` and `?` (propagate) were removed as built-in forms**, and the built-in `catch`
  was replaced by a stdlib macro built on `with-handlers`. Editor grammars dropped the
  `try`, `?`, and `catch` keywords.
- **Prelude auto-import is on by default again.**
- The REPL now loads the stdlib prelude and displays type inference errors.
- Package source and test directories are discovered **recursively**.

## Fixed

- The package test runner exited 0 when test files failed to compile; the `test` command
  now accounts for diagnostic errors in its exit code.
- Compiler crashes in generic `new` expressions, `ValueTuple` IL emission, and out-parameter
  handling.
- IL emitter with recursive generic union types (surfaced by `slist`).
- `Main` wrapper and `begin`-with-void codegen in both emitters.
- Three IL emitter bugs producing `BadImageFormatException` when generic collection types
  appeared in lambdas or built-in conversions: outer type params weren't propagated to
  inner lambdas, `GenericTypeArgs` weren't passed through built-in collection conversion
  lowering, and boxing in generic CLR call contexts used the wrong type representation.
